## 一、产品定位

**BBS AI Studio = 给 BBS FS 拍摄框架加一层 AI 驱动**。两条主线：

1. **动画生成（AI 侧）**——用大模型把想法变成镜头与动作：
   对话 → 分镜/动作数据 → 预览 → 烘焙进影片。
2. **拍摄辅助（原生侧）**——把 AI 嵌进 BBS 原生工作流：
   视频动捕、mod 环境理解、锚点跟随、全界面上下文感知。

设计原则（历史教训的固化）：

- **两线分离**：生成类功能集中在 AI 编辑器；辅助类功能留在各原生面板——
  不混在一起（历史上混在工具面板导致功能割裂）。
- **任何 AI 产出必走正规通道**：分镜→Films、动作→PreviewSystem（预览确认后烘焙）、
  不可绕过；因此**全部可撤销**（AIUndoManager）。
- **上下文只有一个真相来源**：AIWorkspaceContext（你在哪个面板、编辑什么影片/模型），
  所有 AI 功能从这里读，不允许各功能自建碎片状态。
- **兼容性第一**：同一份 bbs_ai 源码面对 2.5/2.6/2.7 三代上游 + 四个 MC 版本；
  2.7-only API 隔离 + BBSFSCompat 运行时守卫。

## 五、核心数据流

```
【生成流】对话/模板 → AI 服务 → storyboard/motion JSON
        → 解析为按钮 → 执行 → Films.mergeInto / PreviewSystem.stage
        → 时间轴同步 → AIUndoManager 登记 → Ctrl+Z 可回退

【动捕流】视频文件 → FFmpeg 抽帧 → ONNX 姿态 → 骨骼映射(六骨)
        → 平滑/脚锁 → MotionData → 导入目录/预览 → 烘焙

【上下文流】面板切换/选中变化 → AIWorkspaceContext.refresh
        → AI 编辑器提示词 / 侧边栏 / 助手菜单 读取

【mod 流】Loader 元数据+注册表+知识库+适配器 → ModInfo[]
        → AIContextService.digest → 分镜/对话提示词
        → mods_report.json（外部共享）
```

### Mod 识别两类论（用户确认）

自动识别的 mod 分两类，**区别对待**：

| 类别 | 识别深度 | AI 可见内容 |
|---|---|---|
| ① BBS 原生插件（bbs-fs addon） | **深**：读取插件注册的 Form/工具/事件/资源等内容 | 插件内容清单可供 AI 调用与引用（生成分镜时可直接使用插件提供的形态/功能） |
| ② 普通第三方 mod | 浅：知识库/注册表统计（现状） | 拍摄视角知识 + 实体/方块资源清单 |

→ 需要新增：addon 插件识别器（枚举 BBS addon 容器与其注册物），接入 AIWorkspaceContext 与提示词。
